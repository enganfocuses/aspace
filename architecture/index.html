Карта системы

Aspace — статическое приложение в браузере. Основной интерфейс, редактор досок, навигация и звонки находятся в index.html. Firebase обеспечивает вход владельца, основное хранение и сигналинг; Cloudflare Worker + D1 резервируют содержимое досок. Сервер приложения не рендерит страницы.

Карта отражает текущую ветку main. Наличие настройки или файла не подтверждает, что правила, секреты, миграции и биллинг уже применены в облаке.

Как сохраняется и восстанавливается доска

  1. Редактор формирует изменение, сохраняет его локально и ставит запись в очередь. Web Locks упорядочивают работу вкладок одного локального участника.
  2. runtime.js выбирает канонический путь личной или общей доски; live-board.js обслуживает чтение, запись, опрос и переключение транспорта.
  3. Основная запись Firebase защищена ETag; D1 использует сравнение ревизий CAS. Нельзя подтверждённую позднюю версию заменить более ранним ответом.
  4. Сетевые ошибки, тайм-ауты, 429, 5xx и распознанные ошибки квоты включают резерв. Обычные 401/403/404, повреждённый JSON и конфликт версий не дают обходить проверку доступа.
  5. _aspaceSync хранит хеш основной версии, состояние резерва и ограниченную цепочку предков. При возвращении Firebase данные возвращаются только при подтверждённой базе/предке.
  6. merge-board.js объединяет независимые изменения объектов. Пересекающиеся правки одного объекта или скалярного поля остаются конфликтом; сохраняются версии для ручного выбора и JSON-экспорта.
  7. Viewer не выполняет восстановление записью. Опрос обновляет роль и отзыв ссылки; скрытые вкладки приостанавливаются. Изменения доступа с неполным подтверждением показывают предупреждение.

Аварийный откат маршрутизации: ?standby=off либо reserve.enabled=false в config.js. Перед откатом экспортировать неотправленные и конфликтующие версии. Отключение резерва не переносит его новые данные в Firebase само по себе.

Звонки и внешние материалы

room0 записывает сигналы в RTDB и читает их через SSE. Call создаёт RTCPeerConnection, получает камеру/микрофон и передаёт медиа участникам. STUN помогает установить прямое соединение, но не заменяет TURN. Сейчас config.js содержит пустой turn и не содержит настроенного metered; это ограничивает соединение через некоторые VPN/NAT. Изменения в коде не подтверждают качество двухсторонней связи в реальной сети.

Переход к доске передаётся событием boardnav. Сеанс persistentCallSession может жить дольше текущего раздела. При отзыве прав или закрытии сеанса необходима очистка подписок и потоков.

YouTube (youtube-nocookie.com), Vimeo, SoundCloud и прямые медиа-URL загружаются с серверов поставщиков. Недоступность, запрет iframe/hotlink, истечение ссылки или отсутствие интернета не исправляются зеркалом D1. PDF.js лежит в vendor/; CDN присутствует как вспомогательный источник. Шрифты и Firebase SDK грузятся извне.

Возможные ошибки и диагностика

СимптомВозможная причинаПроверка / действие
Не открывается приложение / устаревшее менюКеш Service Worker, старая вкладка, ошибка JS или недоступный SDKОбновить страницу, проверить Console/Network, версию sw.js. Перед очисткой хранилища экспортировать черновики и дневник.
Вход не проходитFirebase Auth, сеть, разрешённый домен или состояние учётной записиПроверить Auth в Firebase Console, config.js и домен; резерв D1 не заменяет вход владельца.
401 / 403Истёк token, не тот ownerUid, правила RTDB или отозванный доступПовторно войти; сверить UID в config.js, database.rules.json и Worker. Не ослаблять правила для обхода ошибки.
404 / ссылка отозванаНесуществующая доска, удалённая share meta или неверный путьПроверить ссылку у владельца и индекс. Не трактовать как сетевую аварию, дающую право на резерв.
Доска не сохраняется, 429 / 5xxКвота Firebase, сеть, лимит документа, ошибка Worker/D1Проверить локальное состояние и #usage, сохранить JSON, затем диагностические страницы; не очищать IndexedDB.
Конфликт версий / ETag / CASДва участника изменили один объект либо неизвестна базовая версияЭкспортировать все версии, сравнить содержимое и выбрать проверенную. Не заменять документ последним ответом вслепую.
Резерв пуст или 500Нет схемы D1, binding DB, OWNER_UID / FIREBASE_PROJECT_ID или миграцииПроверить wrangler.toml, /health/db и Cloudflare logs. Не применять две миграции revision к уже обновлённой базе.
Медиа не видно гостюПрава приватного пути, внешний провайдер, превышение размераПроверить share assets и ссылку. Медиа не копируются в D1; приватные /img и /media закрыты правилами.
Камера запрещена / чёрный экранHTTP, запрет браузера, занятая камера, нет устройстваНужны HTTPS/localhost, разрешения браузера и свободная камера. Затем проверить соединение отдельно от захвата.
Участники не соединяютсяTURN не настроен, VPN/NAT или заблокирован SSEПроверить сигналинг и ICE; настроить короткоживущие TURN credentials. Тестировать двумя устройствами в нужных сетях.
Гость не входит в звонокПравила rooms разрешают только владельца; guest-call probe не проходитОтдельные /rooms и /shares/.../room имеют разные права. Проверить фактически опубликованные правила, не только файл.
Дневник не открывается / пропали записиНеверный пароль, другой origin/браузер или очистка localStorageИмпортировать зашифрованную резервную копию с верным паролем; серверной копии и восстановления пароля нет.
Показания лимитов неверныУстаревшие ручные данные или локальные счётчики приняты за биллингСверить период и время с консолью. SSE/WebRTC, другие устройства и протокольные расходы не полностью измерены.
Панель Speechcoach не работаетНет ADMIN_KEY / GitHub token, CORS или другой originПроверить адрес API и ответ без публикации ключа. Вход Aspace не заменяет ключ. История и запомненные файлы со старого адреса не переносятся.
Изменение правил не помоглоФайл в GitHub обновлён, а правила в Firebase не опубликованыОтдельно применить правила через Firebase Console; проверить действующие роли на тестовой ссылке.
Офлайн открывается только оболочкаSDK, документ, картинки или API не успели кешироватьсяКешируются статические файлы, факсимиле — после просмотра. Новый вход, звонок и служебные запросы требуют сети.

Публикация, проверка и восстановление

  1. Статика: коммит main → GitHub Pages workflow → успешный deployment → сверить опубликованный index.html и файлы раздела. При изменении оболочки обновить версию sw.js.
  2. Worker: отдельный manual workflow deploy-aspace-cloudflare-standby.yml, каталог cloudflare, секреты GitHub/Cloudflare. Публикация HTML не обновляет Worker автоматически.
  3. D1: для новой базы schema.sql; для старой без revision — одна соответствующая миграция. Сначала резервная копия; не запускать миграции из документационной страницы.
  4. Firebase: правила из database.rules.json публикуются отдельно. storage.rules относятся к Storage, а не RTDB. Шаблон firebase/rules.owner-guest.template.json не заменяет действующие правила автоматически.
  5. Проверка: node --test tests/*.test.mjs cloudflare/tests/*.test.mjs. Тесты включают синтаксис, UI, сигналинг, локальные лимиты, transport failover, конфликты и дневник. Они не доказывают применение облачных настроек и реальный видеозвонок.
  6. Перед восстановлением сохранить JSON досок, локальные конфликтующие версии и зашифрованный бэкап дневника. Отзыв ссылки не удаляет ранее скачанные копии. Автоматический резерв не заменяет независимую резервную копию.
